# Разработка плагинов для v-ide

v-ide настраивается и расширяется через **Lua**. Это полный справочник для
авторов плагинов: модель рантайма, весь API `vibook`, события и опции, палитра
подсветки синтаксиса и построчный разбор встроенного плагина `links`.

> English version: [`plugin-development.md`](plugin-development.md).

---

## 1. Как загружаются плагины

При старте v-ide создаёт один песочничный Lua-рантайм и выполняет по порядку:

1. **Прелюдию** — определяет таблицу `vibook` и хелперы.
2. **Дефолтные плагины**, вкомпилированные в бинарь (сейчас `links`; см. §8).
3. Ваш **пользовательский конфиг**: `~/.config/v-ide/init.lua`
   (путь переопределяется переменной окружения `V_IDE_CONFIG`; устаревшие
   `VIBOOK_CONFIG` и `~/.config/vi-book/init.lua` работают с предупреждением).

Поскольку ваш конфиг выполняется *после* дефолтных плагинов, вы можете менять
их поведение через опции (например, отключить дефолтный плагин) и добавлять
свои команды, кеймапы, цвета палитры и обработчики событий поверх.

Конфиг — это просто Lua-скрипт. Отдельного манифеста нет: вызывайте функции
`vibook.*`, описанные ниже, и они применяются сразу.

```lua
-- ~/.config/v-ide/init.lua
vibook.opt.leader = " "
vibook.command("hello", function() vibook.buf.set_text("hello!\n") end)
```

## 2. Песочница

Рантайм намеренно маленький и безопасный:

- **Доступны** стандартные библиотеки: `string`, `table`, `math`, `utf8`.
- **Удалены** по умолчанию: `io`, `os`, `debug`, `package`, а также загрузчики
  `dofile`, `loadfile`, `load`/`loadstring`. Доступа к сети нет.
- `print` и `warn` равны `nil` — они испортили бы TUI. Выводите информацию
  через буфер редактора или команды.
- Ошибка плагина показывается в строке статуса; она **никогда** не роняет
  v-ide.
- Долгие скрипты прерываются по бюджету инструкций, поэтому случайный
  бесконечный цикл не подвесит event loop.

Если будущая возможность требует файловой системы или процесса, v-ide
предоставляет под неё *узкую специализированную* функцию (например,
`vibook.open_external`, §6), а не выдаёт плагину сырой `os.execute`.

## 3. Опции — `vibook.opt`

| Опция | Тип | По умолчанию | Назначение |
|-------|-----|--------------|------------|
| `leader` | string | `" "` | Последовательность в нотации Vim для открытия меню. Пустое значение выдаёт ошибку и сохраняет прежнее. |
| `insert_escape` | string | `"jj"` | Insert-маппинг на `<Esc>`; `""` отключает. Явный `vibook.keymap("i", …)` с теми же клавишами важнее. |
| `menu_position` | string | `"bottom"` | Нижняя панель `"bottom"` или модалка `"center"`. |
| `code_editor` | string | `""` | Внешний редактор для код-ссылок; fallback `$EDITOR`. |
| `read_number` | boolean | `false` | Нумерация отображаемых строк Read независимо от Edit. |
| `plugins` | table | `{}` | Тогглы плагинов, напр. `{ links = false }`. |

```lua
vibook.opt.leader = ","
vibook.opt.insert_escape = "jk"
vibook.opt.menu_position = "center"
vibook.opt.code_editor = "nvim"
vibook.opt.plugins = { links = true }
```

### Опции ядра

Для `timeoutlen`, `readonly`, `number` доступны скалярные `vibook.o/go/bo/wo`
и объекты `vibook.opt/opt_local/opt_global` с `:get()`. `bo` обращается к
текущему буферу и меняет только local; `wo` — к текущему окну и меняет local
и default этого окна. `o` меняет effective и global, `go` — только global.
Прежние настройки приложения (`leader`, `wrap`, `read_number`) остаются
скалярами в `opt`.

```lua
vibook.o.timeoutlen = 400
vibook.opt_local.number = true
local show_numbers = vibook.opt.number:get()
vibook.opt.read_number = true
```

Объект хранит снимок значения на момент чтения. Числовые объекты поддерживают
`+`, `-`, `:append()`, `:remove()`; `^` и `:prepend()` для чисел не поддержаны,
как в Neovim. Присвоить объект можно тому же accessor с тем же именем; между
разными accessor используйте скаляр `:get()`.

При начальной конфигурации Edit numbers включены, Read numbers выключены.
Перезагрузка конфига сохраняет runtime-выбор, если скрипт явно его не меняет.
Значения обновляются перед command/event callback; успешные записи до
последующей Lua-ошибки сохраняются.

## 4. Кеймапы — `vibook.keymap(mode, lhs, rhs, opts)`

`mode` — `"n"`, `"i"`, `"x"` или `"v"` (visual, без select), `"o"`
(ожидание оператора), `"c"` (командная строка и поиск) либо список режимов,
например `{ "n", "x" }`. Каждый режим получает отдельное определение, как в
`vim.keymap.set`. Ошибка режима останавливает текущий список без отката
предыдущих элементов; следующие определения обрабатываются. Список с
нестроковым элементом отклоняется целиком. Неверные типы,
неподдержанные опции и пустая левая часть дают ошибку. Ошибка самого init.lua
имеет приоритет.

Четвёртый аргумент принимает булевы `remap`, `nowait`, `unique`, `silent`.
По умолчанию маппинги нерекурсивны; `remap = true` включает повторный маппинг
клавиш RHS. `nowait = true` не ждёт более длинного совпадения; `unique = true`
даёт E227 вместо перезаписи. `silent` принимается как no-op.

Правая часть смешивает клавиши и `<Cmd>команда<CR>`: команды выполняются по
порядку, сохраняя режим. Незакрытый Cmd даёт E1255. Начальный `:` — обычная
клавиша: `:w` набирает draft, `:w<CR>` отправляет его в Normal. Для сохранения
режима Insert, Visual и текущего draft используйте `<Cmd>w<CR>`.

Маппинги важнее встроенных клавиш, включая leader, `<F1>`, `?`, `:` и `<C-w>`.
Нерекурсивные клавиши доходят до встроенных действий: RHS `?` открывает справку.
В read, панелях и всплывающих окнах маппинги не действуют.

```lua
vibook.keymap("n", "<C-s>", "<Cmd>w<CR>")        -- Ctrl-s сохраняет
vibook.keymap("i", "<C-s>", "<Cmd>w<CR>")        -- ...и в insert, не выходя из него
vibook.keymap("n", "H", "0")             -- H в начало строки
vibook.keymap("n", "Y", "y$")            -- Y копирует до конца строки
vibook.keymap("n", "<Leader>d", "dd")    -- leader, затем d
vibook.keymap("o", "L", "$")             -- dL удаляет до конца строки
vibook.keymap("n", "Q", "j<Cmd>only<CR>k") -- клавиши вокруг команды
vibook.keymap({ "n", "x" }, "J", "j", { remap = true })
```

Левая часть — одна или несколько клавиш, каждая с модификаторами или без, в
нотации vim:
`<C-x>` (Ctrl), `<M-x>` или `<A-x>` (Alt), `<S-Tab>` (Shift), `<D-x>` (Super/Cmd)
и именованные `<Esc> <CR> <BS> <Tab> <Del> <Insert> <Home> <End> <PageUp>
<PageDown> <Up> <Down> <Left> <Right> <F1>`–`<F12> <Space> <lt> <Bar> <Bslash>`.
Имена регистронезависимы; неизвестное `<…>` читается как обычные символы.
Управляющие символы в Lua-строке — тоже клавиши: `"\t"` — это `<Tab>`, `"\27"` —
`<Esc>`, `"\1"` — `<C-a>`. `<Leader>` (в любом регистре) — это
`vibook.opt.leader` на конец `init.lua`, порядок строк неважен. Раскрывается в
обеих частях, кроме текста внутри `<Cmd>`. Leader может состоять из нескольких
клавиш: `vibook.opt.leader = "<C-a>x"`.

Пока многоклавишная левая часть не набрана целиком, набранный префикс виден
справа в статусе, а редактор ждёт продолжения до одной секунды. Потом префикс
выполняется как обычные клавиши: полный leader при возможном более длинном
маппинге открывает меню после паузы, иначе — сразу. Неполный или несовпавший
leader возвращает клавиши редактору. Встроенный вызов меню не виден в `:map`
и не удаляется `:mapclear`. В insert ожидающий
символ рисуется на месте курсора, но в текст попадает, только когда маппинг
разрешится.

Правая часть, равная `<Nop>` (в любом регистре), отключает клавишу.

Маппинги можно просмотреть через `:map`, `:imap` или фильтр `:nmap Q`.
Общие определения сохраняются группой до изменения отдельного режима.
`:messages` показывает последние 1000 непустых сообщений, включая ошибки
плагинов и повторы; `:messages clear` очищает историю. Длинный вывод доступен
через общий пейджер, описанный в руководстве пользователя.
Сообщения при наборе Ex-команды или поиска сохраняют набранный текст и не
требуют подтверждения.

## 5. Меню, команды, события

### Пункты меню — `vibook.menu_item(key, label, rhs)`

```lua
vibook.menu_item("g", "Open scratch", ":new scratch")
```

### Команды — `vibook.command(name, fn)`

Вызываются как `:name`. Внутри читайте и переписывайте активный буфер.

```lua
vibook.command("upper", function()
  vibook.buf.set_text(vibook.buf.get_text():upper())
end)

vibook.command("wc", function()
  local n = select(2, vibook.buf.get_text():gsub("%S+", ""))
  vibook.vault.create("wordcount-" .. n)
end)
```

### События — `vibook.on(event, fn)`

| Событие | Аргумент | Когда срабатывает |
|---------|----------|-------------------|
| `note_open` | — | заметка только что открыта |
| `note_save` | — | заметка только что записана |
| `follow_link` | `target` (string) | пользователь переходит по `[[ссылке]]` |

```lua
vibook.on("note_open", function()
  -- например, нормализовать буфер при открытии
end)

vibook.on("follow_link", function(target)
  -- решить, как открыть цель ссылки (см. §6 и §9)
end)
```

Все обработчики одного события выполняются в порядке регистрации.

## 6. Открытие заметок и файлов

Эти функции выражают *намерение*; v-ide выполняет действие после возврата
из обработчика.

- `vibook.open(target)` — открыть `target` внутри v-ide (путь заметки, напр.
  `"ideas.md"` или вложенный `"proj/spec.md"`).
- `vibook.open_external(target)` — открыть `target` во внешнем редакторе
  (`vibook.opt.code_editor`, иначе `$EDITOR`). v-ide находит файл в волте
  (по относительному пути, иначе по имени) и приостанавливает TUI на время
  работы редактора.
- `vibook.vault.create(name)` — создать новую заметку `name`.
- `vibook.vault.open(name)` — псевдоним `vibook.open` для симметрии с
  остальными `vault.*`.

## 7. Чтение состояния

### Буфер — `vibook.buf`

- `vibook.buf.get_text()` → активный буфер строкой.
- `vibook.buf.set_text(s)` → заменить активный буфер.
- `vibook.buf.get_cursor()` → символьный индекс курсора.

### Волт — `vibook.vault`

- `vibook.vault.notes()` → список путей заметок в волте.
- `vibook.vault.tags()` → список `#тегов` по всему волту.
- `vibook.vault.backlinks(path)` → заметки, ссылающиеся на `path`.

*Волт* — это активная папка, с которой открыт v-ide; поиск тегов и ссылок
ограничен ею.

Волт сканируется при первом запросе (или пикере, переходе по ссылке, дереве), а
не на старте. Если скан упал, эти функции бросают Lua-ошибку `vault: <причина>`,
следующий вызов повторяет попытку.

Сохранение или создание заметки в v-ide обновляет эти списки, перечитывая только
эту заметку. Заметки, добавленные, изменённые, удалённые или переименованные вне
v-ide, подхватываются так же — за доли секунды; переименование или удаление папки
перечитывает только заметки внутри неё. Если изменённую заметку не прочитать,
прежние списки остаются, а в строке статуса — `vault: <заметка>: <причина>`. Если
watcher файлов не запустился, в строке статуса один раз появится
`vault: watch: <причина>`, и внешние изменения не подхватываются; на Linux обычно
это значит, что лимита inotify `fs.inotify.max_user_watches` мало для вольта. Если
лимит кончится позже, по мере роста вольта, в строке статуса один раз появится
`vault: watch: <причина>`, и папки, созданные после этого, не отслеживаются;
остальное работает как прежде.
Если watcher сообщил о потере событий или об ошибке, вольт пересканируется целиком,
а ошибка показывается как `vault: watch: <причина>`. Если при этом какую-то заметку
не прочитать, списки всего вольта остаются прежними, в строке статуса один раз
появится `vault: <причина>`, а rescan повторится при следующем изменении любого файла
вольта — починка заметки сама обновит списки.

## 8. Палитра подсветки — `vibook.color(name, spec)`

Код-блоки подсвечиваются грамматиками tree-sitter, которые ставят
`v-ide grammar fetch` и `v-ide grammar build` (rust, python, javascript, typescript,
tsx, json, bash, go, c, toml, html, yaml и популярные алиасы; подробно — в manual).
Перекрашивайте любой токен — или любой markdown-стиль — из конфига.

Поля `spec`: `fg` (цвет), `bold`, `italic`, `underline`, `dim`. `fg`
принимает имена терминальных цветов (`"red"`, `"magenta"`, `"cyan"`, …) и hex
(`"#82aaff"`).

```lua
vibook.color("keyword",  { fg = "magenta", bold = true })
vibook.color("string",   { fg = "green" })
vibook.color("number",   { fg = "yellow" })
vibook.color("comment",  { fg = "#6a737d", italic = true })
vibook.color("function", { fg = "blue" })
vibook.color("type",     { fg = "cyan" })

-- markdown-стили тоже настраиваются:
vibook.color("heading1", { fg = "magenta", bold = true })
vibook.color("link",     { fg = "blue", underline = true })
```

**Имена токенов кода:** `keyword`, `string`, `number`, `comment`, `function`,
`type`, `constant`, `variable`, `operator`, `punctuation`, `property`,
`attribute`.

**Имена markdown-стилей:** `text`, `heading1`, `heading2`, `heading3`, `bold`,
`italic`, `codespan`, `codeblock`, `frame`, `link`, `hashtag`, `quote`,
`frontmatter`.

> v-ide — терминальное приложение: оно не выбирает *шрифт*. Для лигатур и
> глифов поставьте в терминале Nerd Font (установщик предлагает
> JetBrainsMono Nerd Font).

## 9. Разбор примера — плагин `links`

Это дефолтный плагин, поставляемый в бинаре (`crates/lua/assets/plugins/links.lua`). Он
решает, как открыть цель `[[ссылки]]`: текстовые заметки — в v-ide, файлы с
кодом — в вашем редакторе, голые имена — отдаёт собственному резолверу v-ide.

```lua
local text_ext = {
  md = true, markdown = true, txt = true, text = true, org = true, rst = true,
}

local function disabled()
  return vibook.opt.plugins ~= nil and vibook.opt.plugins.links == false
end

local function extension(target)
  return target:match("%.([%w]+)$")
end

vibook.on("follow_link", function(target)
  if disabled() then
    return
  end
  local ext = extension(target)
  if ext == nil then
    return                      -- [[note]] → v-ide резолвит алиасы/якоря
  end
  if text_ext[ext:lower()] then
    vibook.open(target)         -- [[notes.md]] → открыть в v-ide
  else
    vibook.open_external(target) -- [[main.rs]] → внешний редактор
  end
end)
```

Как это работает:

1. `vibook.on("follow_link", …)` регистрирует обработчик, получающий строку
   цели ссылки (всё внутри `[[ ]]`, без `#якоря`/`|алиаса`).
2. `disabled()` уважает `vibook.opt.plugins.links = false`, чтобы плагин можно
   было выключить, не удаляя.
3. Цель **без** расширения завершает обработчик рано. Намерения открыть не
   создано, поэтому v-ide откатывается к встроенному резолверу (коллизии
   имён, алиасы, якоря).
4. **Текстовое** расширение вызывает `vibook.open` — v-ide открывает внутри.
5. Любое другое расширение вызывает `vibook.open_external` — v-ide находит
   файл в волте и передаёт его вашему редактору.

### Свой вариант

Отключите дефолтный и зарегистрируйте свою маршрутизацию — например, открывать
картинки просмотрщиком:

```lua
vibook.opt.plugins = { links = false }

vibook.on("follow_link", function(target)
  local ext = (target:match("%.([%w]+)$") or ""):lower()
  if ext == "png" or ext == "jpg" then
    vibook.open_external(target)   -- code_editor указывает на просмотрщик
  elseif ext == "md" or ext == "" then
    vibook.open(target)
  else
    vibook.open_external(target)
  end
end)
```

## 10. Сборка и тесты

```
cargo build --release   # один статический бинарь target/release/v-ide
./install.sh            # сборка + установка + конфиг + загрузка Nerd Font
cargo test              # каталог tests/ — иммутабельный контракт
```

Добавляя новую возможность в рантайм, покрывайте её тестом в `tests/`
(загрузите скрипт в `PluginHost`, затем проверьте наблюдаемый эффект),
по образцу существующих файлов `lua_*`.
